# ЧудоСуфлёр — прототип

Сайт: https://m7024489.github.io/chudosufler/ (обновляется автоматически после каждого изменения кода)

Веб-страница для одного смартфона. Она снимает актёра на фронтальную камеру, пишет звук и во время записи воспроизводит реплики партнёра (Пети). Запись останавливается кнопкой «Стоп», после чего видео можно посмотреть, скачать или сохранить в «Фото».

Распознавания речи и автоматического суфлёра здесь пока нет: это этапы 2 и 3.

---

## 1. Оценка реализуемости (до проверки на телефонах)

| Вопрос | Оценка |
|---|---|
| Камера, запись и воспроизведение звука одновременно в браузере | Реализуемо: это стандартные API (getUserMedia, MediaRecorder, Web Audio). Главный риск — поведение звука на iPhone, его и проверяет этап 1. |
| Голос партнёра в итоговом видео | Есть два способа, оба встроены (см. ниже). Вариант 2 не зависит от акустики и подавления эха, поэтому надёжнее. |
| Распознавание речи (этап 2) | Браузерный SpeechRecognition на iPhone и Android может конфликтовать с одновременной записью: он сам захватывает микрофон. Если так и окажется, нужен запасной путь через сервер: потоковая отправка аудио на STT. |
| Задержка ответа партнёра до 1 с | С заранее подготовленными аудиофайлами реплик воспроизведение начинается практически сразу. Основную задержку даст распознавание (этап 2). |

**Минимальный стек:** React + TypeScript + Vite. Это статический сайт, сервер на этапе 1 не нужен.

**Нужен ли сервер:**
- Этап 1: нет. Достаточно любого статического HTTPS-хостинга.
- Этап 2: только если браузерное распознавание не будет работать вместе с записью. Бесплатный вариант — свой сервер с Vosk (есть русская модель) и WebSocket. Платные — Yandex SpeechKit, Deepgram и аналоги. Ключи хранятся только на сервере.

**Как проверить без платных API:**
- Голос партнёра можно взять из синтеза речи, встроенного в телефон (кнопка уже есть).
- Или записать реплики Пети своим голосом прямо в приложении.
- Или загрузить готовые аудиофайлы.

### Ожидаемые ограничения (не проверены, это то, что тест должен подтвердить или опровергнуть)

**iPhone / Safari**
- MediaRecorder пишет MP4 (H.264 + AAC). Такой файл открывается везде.
- Пока включён микрофон, iOS переводит звук в режим «разговора». Голос партнёра из динамика может стать тише.
- Подавление эха может частично вырезать голос партнёра из микрофона. Тогда при варианте 1 партнёра в записи будет плохо слышно.
- Синтез речи срабатывает только по нажатию пользователя. Прототип «разблокирует» его в момент нажатия «Начать запись».
- Если свернуть Safari или заблокировать экран, камера и запись прерываются. Прототип не даёт экрану гаснуть во время записи (Wake Lock, iOS 16.4+).
- Сохранение в «Фото» — через кнопку «Поделиться» → «Сохранить видео».

**Android / Chrome**
- В зависимости от версии Chrome формат будет MP4 или WebM. WebM может не открыться в некоторых галереях и на iPhone. Формат выбирается в настройках, его видно в журнале.
- Подавление эха может так же вырезать голос партнёра.
- Синтез речи иногда не сообщает об окончании фразы. Для этого есть страховочный таймаут.

## 2. Что умеет прототип этапа 1

- Предпросмотр фронтальной камеры (зеркальный только на экране, запись не зеркалится).
- Статус микрофона и индикатор уровня, индикаторы «REC» и «Говорит партнёр».
- Текущая реплика партнёра и следующая реплика актёра.
- Кнопки «Начать запись», «Следующая реплика», «Повторить», «Стоп».
- Первая реплика Пети звучит автоматически через 1 с после старта (можно отключить).
- **Вариант 1** — «динамик → микрофон»: голос партнёра звучит из динамика и попадает в видео только через микрофон.
- **Вариант 2** — «подмешивать в дорожку»: голос партнёра звучит из динамика и одновременно напрямую подмешивается в звуковую дорожку видео через Web Audio. Для этого нужны аудиозаписи реплик (синтез речи браузера подмешать нельзя). Есть опция «глушить микрофон, пока говорит партнёр», чтобы в записи не было двойного голоса.
- Источник голоса партнёра: синтез речи телефона или свои аудиозаписи. Записи можно сделать прямо в приложении или загрузить файлами; они хранятся в браузере.
- Переключатели echoCancellation, noiseSuppression и autoGainControl.
- Автовыбор формата (MP4 в приоритете) и ручной выбор.
- Итоговое видео можно посмотреть, скачать или отправить через «Поделиться» (на iPhone оттуда же — «Сохранить в Фото»).
- Журнал диагностики: браузер, поддерживаемые форматы, параметры треков, события mute/ended, ошибки, размер и длительность записи. Журнал можно скопировать или скачать.
- Понятные сообщения при запрете доступа к камере или микрофону, если они заняты или страница открыта не по HTTPS.

## 3. Запуск

Нужен Node.js 18 или новее.

```bash
npm install
npm run dev
```

В терминале появятся адреса вида `https://192.168.x.x:5173`.

**Тест с телефона в той же Wi-Fi сети:**
1. Откройте этот адрес на телефоне. Сертификат самоподписанный, поэтому браузер предупредит:
   - iPhone: «Подробнее» → «посетить этот веб-сайт»;
   - Android: «Дополнительные» → «Перейти на сайт».
2. Разрешите доступ к камере и микрофону.

**Статическая сборка для хостинга:**

```bash
npm run build      # результат в папке dist/
```

Папку `dist/` можно выложить на любой HTTPS-хостинг: Netlify (перетащить папку на app.netlify.com/drop), Vercel, GitHub Pages, Cloudflare Pages. Сервер и ключи не нужны.

## 4. Как тестировать на iPhone и Android

Перед тестом: громкость на максимум, беззвучный режим выключен (на iPhone переключатель сбоку), без наушников, телефон на штативе на расстоянии около 1 м.

**Тест A — вариант 1, синтез речи**
1. Настройки: «Вариант 1», «Синтез речи телефона». Подавление эха включено.
2. Нажмите «Включить камеру» → «Начать запись». Петя должен заговорить сам.
3. Ответьте за Машу, нажмите «Следующая реплика», затем один раз «Повторить». Дойдите до конца и нажмите «Стоп».
4. Посмотрите видео и сохраните его.

**Тест B — то же, но с выключенным подавлением эха**
Выключите подавление эха и нажмите «Перезапустить камеру». Сравните громкость Пети в записи с тестом A.

**Тест C — вариант 2, свои записи**
1. В разделе «Аудио реплик партнёра» запишите три реплики Пети.
2. Настройки: «Вариант 2». Пройдите сцену. Затем повторите с включённой опцией «Глушить микрофон, пока говорит партнёр».

**По каждому тесту отметьте:**
- слышен ли Петя из динамика во время записи и насколько громко;
- слышен ли Петя в итоговом видео;
- слышна ли Маша в итоговом видео;
- есть ли эхо или двойной голос;
- не прервалась ли запись (длительность видео совпадает с реальной);
- открывается ли файл и сохраняется ли в галерею.

После каждого теста нажмите «Журнал диагностики» → «Скачать .txt» и пришлите файл вместе с моделью телефона и версией iOS или Android. Особенно важны строки с `mute`, `ended`, `ERROR` и формат записи.

## 4а. Автоматический суфлёр и титры (этапы 2–3)

- **Титры поверх видео**: сверху крупно реплика актёра; уже сказанные слова подсвечиваются зелёным (в режиме распознавания). Пока говорит партнёр, над ней видна его реплика.
- **Переход к следующей реплике партнёра** (Настройки):
  - *Авто: по распознаванию речи* — браузерный SpeechRecognition. Партнёр вступает, когда прозвучало ≥60% слов реплики **и её конец**, а затем выдержана пауза. Пауза посреди фразы переход не запускает; замена отдельных слов не мешает. Если распознавание недоступно или выдаёт ошибку, приложение само переключается на «по паузе».
  - *Авто: по паузе в голосе* — без распознавания и без интернета: актёр проговорил хотя бы половину ожидаемой длины реплики, потом замолчал на заданное время.
  - *Вручную* — кнопкой.
- **Пауза перед ответом**: 0,5 / 1 / 2 с.
- **Громкость партнёра**: ползунок, его можно двигать и во время записи (применяется со следующей реплики).
- Пока говорит партнёр, его голос не считается речью актёра.

## 5. Статус проверки

**Подтверждено на реальном телефоне (пользователь, 19.11.2026):** камера, запись и голос партнёра работают одновременно; при выключенном подавлении эха и включённом автоусилении эха нет, оба голоса есть в записи. Замечание: партнёр громче актёра — добавлен регулятор громкости.

**Авто-переход и титры** проверены только в headless Chromium (режим «по паузе» и запасной путь при неработающем распознавании). Работа распознавания речи на телефоне вместе с записью пока не проверена.

**Подтверждено** (только на компьютере, в headless Chromium с виртуальной камерой и микрофоном):
- сборка TypeScript проходит без ошибок;
- камера открывается, запись идёт, реплики проигрываются во время записи, «Повторить» и «Стоп» работают, файл скачивается;
- в варианте 2 голос партнёра действительно попадает в звуковую дорожку итогового файла (проверено анализом звука);
- запись не прерывается во время воспроизведения.

**Не подтверждено — нужно проверить на реальных устройствах:**
- всё, что относится к iPhone/Safari и Android/Chrome;
- громкость динамика при включённом микрофоне;
- попадание голоса партнёра в запись в варианте 1;
- уровень эха;
- синтез речи во время записи;
- сохранение в «Фото» или галерею.

Утверждать, что прототип работает на iPhone или Android, можно будет только после теста на реальном телефоне.

## 6. План следующих этапов (после вашего подтверждения этапа 1)

1. **Этап 2.** Добавить `webkitSpeechRecognition` параллельно с записью и выводить распознанный текст на экран. Проверить, не глушит ли он запись. Если глушит, сделать запасной путь: отправку аудио на сервер через WebSocket (Vosk бесплатно или облачный STT).
2. **Этап 3.** Сопоставлять распознанный текст с ожидаемой репликой: нечёткое сравнение по словам и доля совпадения. Конец реплики определять так: совпадение не меньше порога, последние слова реплики уже прозвучали, затем пауза 0,5 / 1 / 2 с. Пока говорит партнёр, распознавание не слушать. Ручной переход остаётся.
3. **Этап 4.** Записать полную сцену и проверить качество звука и видео.
